QAS 03 / 신뢰성 · 복구성

복구성

센터 장애 시 데이터를 잃지 않고 DR로 전환해 우선 업무부터 복구한다.

검토 결과 R1단일 쓰기 주체와 명확한 저장 경계로 데이터 보존과 안전한 전환을 우선한다.↓
요구사항전략 3개장단점Trade-off선택 근거·보완점조사 근거

확정 요구사항

QAS 03
RPO 0데이터 손실 불허
RTO 3시간복구 목표 상한
60~80%일정 시간 축소 운영 허용

센터 장애 발생 시 DR 환경으로 최초 전환을 자동 수행하고, 서비스 요청 → 계약 조회 → 견적(보험료 산출) 순서로 복구한다. RTO 목표는 3시간 이내이며 복구 완료 여부는 사용자가 수동으로 판단한다. 데이터 손실은 허용하지 않으며, 미완료 작업은 임시 저장된 데이터까지 보존한다. 복구 후 일정 시간은 정상 대비 약 60~80% 수준의 축소 운영을 허용하고, 원센터로의 Failback은 사용자가 수동으로 수행한다.

측정 범위와 공통 설계 조건
  • 센터 장애만 대상으로 하며 Private Cloud를 우선한다. 데이터 훼손·랜섬웨어는 범위에서 제외한다.
  • 성공 응답한 업무 데이터와 저장 완료한 임시 데이터는 생존 센터에 영속화한다. 자동 전환 시 이중 쓰기를 차단한다.
  • 최초 DR 전환은 자동, 복구 완료 판정과 Failback은 수동이다.

Style·Pattern·Tactics 통합 전략

3 ALTERNATIVES

같은 QAS를 달성하기 위한 세 가지 대안이다. 각 전략의 구조와 동작을 먼저 살펴본 뒤 장단점과 Trade-off를 비교한다.

R1

단일 쓰기 주체와 동기 복제 기반 일괄 DR 전환

선택 전략

계층형 업무 애플리케이션과 데이터 저장소를 DR 센터에 사전 준비하고 쓰기 주체는 한 센터로 제한한다. 센터 소실 후에도 남는 사본에 업무 저장과 임시 저장이 영속화되었음을 확인한 뒤 성공을 응답한다. 센터 장애를 감지하면 기존 쓰기를 차단하고 DR 저장소와 애플리케이션을 자동 전환한다. 전체 실행 환경을 준비한 뒤 사용자 업무는 지정된 우선순위로 개방한다. 완료 판정과 원센터 복귀는 사람이 수행한다.

R1의 Style, Pattern, Tactics
StyleModule의 Layers + C&C의 Call-and-Return·Repository 스타일. 배치 관점에서 주센터/DR센터를 나누며 센터 배치는 별도 스타일 이름으로 만들지 않는다.
PatternWarm Standby와 주·대기 복제 구성. DB 대기 서버에 관한 조사 원리를 전체 업무의 사전 준비 DR 구조에 적용한 설계안이다.
Tactics센터 간 동기 영속화, 장애 감지, 기존 쓰기 차단(fencing), 자동 승격·경로 전환, 복제 상태 대조, 우선순위 개방, 수동 완료 판정·Failback.
동작
주센터 업무 저장 → DR센터 영속화 확인 → 고객 성공 응답. 센터 장애 시 쓰기 차단 → DR 자동 전환 → 우선순위 개방 → 수동 판정.
QAS 연결
센터 장애의 RPO 0을 저장 완료 경계와 연결하고 RTO 3시간 이내를 목표로 한다. 저장 완료한 임시 작업까지 같은 내구성 경계를 적용한다.
적용 한계
센터 간 왕복 지연이 쓰기 응답에 더해진다. 원격 영속화를 확인하지 못할 때 쓰기를 계속 성공 처리하면 RPO 0 근거가 깨질 수 있다. 자동 전환은 DB 복제 설정만으로 완성되지 않는다.

R2

업무 서비스 분리와 우선순위별 단계 복구

서비스 요청·계약 조회·견적을 독립적으로 개방할 수 있는 실행 서비스로 나누고 각 서비스의 데이터와 DR 실행 환경을 사전 준비한다. 공통 기반과 데이터 안전성을 확보한 뒤 서비스 요청, 계약 조회, 견적 순서로 실제 업무를 검증하며 개방한다. 마이크로서비스의 독립 실행·배포 경계를 복구 단위로 활용하고 주·대기 구조와 동기 영속화를 함께 적용한다. 복구의 단위는 단순 기동 순서가 아닌 업무별 사용 가능 상태다.

R2의 Style, Pattern, Tactics
StyleMicroservices + C&C의 Call-and-Return·Repository 스타일. 독립 배포의 경계를 복구·개방 경계로 활용하는 프로젝트 적용안이다.
Pattern서비스별 Warm Standby + 필요한 외부 의존성의 Circuit Breaker. ‘단계 복구’를 조사에 없는 새 패턴 이름으로 분류하지 않는다.
Tactics복구 단위 분리, 공통 의존성 선행 준비, 서비스별 자동 활성화·검증, 동기 영속화·단일 쓰기 보장, 우선순위 개방, 허용된 축소 운영, 수동 완료 판단.
동작
자동 기반 전환 후 1 서비스 요청 개방 → 2 계약 조회 개방 → 3 견적 개방. 각 단계에서 입력·처리·정상 결과를 확인하고 사용자가 전체 완료 선언.
QAS 연결
QAS에 정해진 복구 우선순위를 서비스 경계로 표현한다.
적용 한계
서비스 요청에 계약 확인이 필요하면 계약 저장소·최소 조회 기반은 먼저 준비한다. 사용자 개방 순서와 내부 기동 순서는 다를 수 있다. 서비스 분리만으로 RPO 0·3시간을 보장하지 않으며 운영·개발 비용이 증가한다.

R3

영속 접수와 이벤트 재전달을 결합한 작업 연속성 복구

업무 상태·접수번호·임시 저장·처리할 이벤트를 복구 가능한 저장 경계에 남기고 센터 장애 뒤 DR에서 미완료 후속 작업을 다시 전달한다. 원본 업무 상태와 outbox는 동일 트랜잭션으로 기록하고 센터 간 동기 영속화를 확인한다. DR에서 단일 쓰기 주체를 확보한 후 큐와 작업자를 재개한다. 중복 메시지는 같은 업무 결과로 수렴하도록 처리한다. 저장 데이터 보존과 미완료 작업의 이어 처리를 함께 다루는 이벤트 기반 복구 전략이다.

R3의 Style, Pattern, Tactics
StyleC&C의 Event·Repository·Call-and-Return 스타일. 동기 접수 경로와 비동기 작업 재개 경로를 구분한다.
PatternTransactional Outbox + Queue-Based Load Leveling + Warm Standby. Event Sourcing 전면 도입이나 전체 이력 재생을 필수로 추가하지 않는다.
Tactics동기 영속화, 원자적 상태·이벤트 기록, 처리 상태 확인, 미완료 이벤트 재전달, 멱등 처리·중복 방지, 제한된 재시도, 외부 실행 결과 대사, 우선 업무부터 재개.
동작
주센터 업무·outbox 저장 → DR 영속 사본. 장애 후 쓰기 차단·자동 승격 → 미완료 이벤트 확인 → 큐 재전달 → 멱등 작업자 → 업무 결과 대사.
QAS 연결
저장 완료한 데이터의 RPO 0과 접수 후 작업의 연속성을 연결한다. 서비스 요청·계약 조회·견적의 순서로 개방하며 사람의 복구 완료 판정을 유지한다.
적용 한계
outbox만으로 센터 장애 RPO 0이 되지 않으며 원격 영속화가 필요하다. 메시지 수신을 외부 지급 실행 완료와 동일시하지 않는다. 적체 재처리가 신규 업무를 압도하지 않게 제어하고 모든 이벤트 처리 완료를 복구 선언의 필수 조건으로 임의 추가하지 않는다.

전략별 장단점

PROS & CONS

R1 단일 쓰기 주체와 동기 복제 기반 일괄 DR 전환

장점. 단일 쓰기 주체로 데이터 정합성을 관리한다. 전체 환경의 전환 절차가 비교적 단순하고 RPO 0의 저장 경계를 명확히 할 수 있다.

단점. 원격 영속화 확인으로 쓰기 지연이 늘어난다. 공통 기반과 전체 환경의 준비 상태가 복구에 영향을 준다.

R2 업무 서비스 분리와 우선순위별 단계 복구

장점. 업무별로 검증·개방할 수 있어 복구 우선순위를 실행 단위로 관리하기 좋다.

단점. 서비스별 복제·전환·의존성을 관리해야 한다. 개방 순서와 내부 기동 순서가 달라질 수 있다.

R3 영속 접수와 이벤트 재전달을 결합한 작업 연속성 복구

장점. 저장 데이터뿐 아니라 미완료 후속 작업을 이어 처리하기 좋다. 작업 상태를 추적하며 누락을 확인할 수 있다.

단점. 중복 처리·외부 실행 결과 대사·적체 해소가 필요하다. outbox와 큐만으로 RPO 0이 보장되지는 않는다.

선택 전략 · R1

단일 쓰기 주체와 동기 복제 기반 일괄 DR 전환

센터 장애, RPO 0, 최초 자동 전환이라는 핵심 요구를 비교적 단순한 구조로 다룰 수 있다. 현재 요구에서는 R2의 세밀한 서비스별 복구나 R3의 후속 작업 재개보다 데이터 보존과 안전한 전환을 우선한다.

받아들이는 Trade-off

업무별 독립 복구와 미완료 작업 재개에 특화한 구조 대신, 단일 쓰기 주체와 일괄 전환 절차를 선택한다. 원격 확인 지연과 공통 기반의 복구 준비 상태를 관리해야 한다.

보완점·개선점

서비스 요청 → 계약 조회 → 견적 순서로 업무를 개방한다. 센터 간 동기 영속화와 기존 쓰기 차단을 적용하고, RTO 3시간 이내와 월간 가용률 99.9% 이상을 함께 관리한다.
